# Theme

## Context and Design Philosophy

This segment defines the visual language of the app: Material You theming, dark mode, typography, shapes, and the category color system. It is a pure UI concern — no domain types or repository calls originate here.

The guiding principle is to stay as close to Material 3 defaults as possible and only deviate where the app has a specific need (category colors being the primary case).

## TrackrTheme

A single `TrackrTheme` composable wraps the entire app. It:

- Applies dynamic color (`dynamicDarkColorScheme` / `dynamicLightColorScheme`) on Android 12+ (API 31+)
- Falls back to a fully specified `lightScheme` / `darkScheme` on older devices (see Fallback Palette below)
- Switches between light and dark schemes via `isSystemInDarkTheme()`
- Uses default Material 3 typography and shapes throughout

```
TrackrTheme
    ├── Android 12+  → dynamicDarkColorScheme(context) / dynamicLightColorScheme(context)
    └── Android <12  → lightScheme / darkScheme (brand-seeded, see below)
```

## Fallback Palette

The fallback color scheme is generated by the [Material Theme Builder](https://material-foundation.github.io/material-theme-builder/) from the brand seed color. The output includes:

- `lightScheme` / `darkScheme` — standard light and dark variants
- `mediumContrastLightColorScheme` / `mediumContrastDarkColorScheme` — medium contrast accessibility variants
- `highContrastLightColorScheme` / `highContrastDarkColorScheme` — high contrast accessibility variants

All color constants live in `Color.kt`; `Theme.kt` assembles them into schemes. This mirrors the approach used in GolfScore (`~/AndroidStudioProjects/GolfScore`), which was also generated by Material Theme Builder.

**Brand colors:**
- Dark blue: `#04325C`
- Green: `#148244`
- Yellow: `#fcd214`
- Light blue: `#47aadc`

The fallback palette in `Color.kt` was seeded from `#37618E` (borrowed from GolfScore). It could be regenerated from the true brand colors using the [Material Theme Builder](https://material-foundation.github.io/material-theme-builder/) with the dark blue `#04325C` as the primary seed. `Theme.kt` is unchanged if the brand color ever changes — only `Color.kt` needs replacing.

**Disabling dynamic color** — switching to always use the brand palette is a one-line change: `dynamicColor: Boolean = true` → `false` in `TrackrTheme`. The fallback scheme is always present; no other changes needed.

**Contrast variants:** `TrackrTheme` selects the appropriate scheme based on `isSystemInDarkTheme()` only in v1 (standard light/dark). Medium and high contrast schemes are generated and available for a future accessibility setting.

## Dark Mode

Driven entirely by `isSystemInDarkTheme()` — no in-app toggle in v1. Dynamic color and the fallback palette both have separate light and dark variants handled by Material 3's color scheme generation.

## Typography

Default Material 3 type scale throughout. No custom fonts in v1. If a custom font is added later, it replaces the default in `TrackrTheme` only — no call sites change.

## Shapes

Default Material 3 shape scale throughout (rounded corners per M3 spec). No overrides in v1.

## Category Color System

Each `Category` carries a `color: Long` (ARGB). Category colors appear in:
- Category chips on the timeline filter row
- Event rows in the timeline (circle avatar)
- Category list rows (circle avatar)
- The category edit screen color picker's palette swatches, and the live preview card (which reuses `EventRow`, so circle avatar)

### Usage in UI

Category color usage differs by surface:

**Container background** (chips, edit screen color picker palette swatches): the category color fills the entire surface; text and icons on top use `foregroundColorForBackground(color)` — white for dark backgrounds, black for light, per WCAG relative luminance. Material 3's `contentColorFor()` is not used here since category colors are arbitrary user values outside the app's tonal palette.

**Circle avatar** (timeline event rows, category list rows): the category color fills a 48dp filled circle around the category emoji; the emoji is centered inside the circle using `foregroundColorForBackground(color)`. The surrounding row surface itself uses the M3 surface container color (event rows) or the list background (category list rows), not the category color.

### Preset Palette

The category color picker (defined in `category-management`) presents a fixed preset palette. Colors are chosen to:
- Be visually distinct from one another
- Work acceptably in both light and dark mode as container backgrounds
- Pass WCAG AA contrast with both white and black text (so the foreground computation is predictable)

Palette (12 colors, defined as `Long` ARGB constants in the theme layer):

| Name | ARGB |
|---|---|
| Red | `0xFFE53935` |
| Orange | `0xFFFB8C00` |
| Amber | `0xFFFFB300` |
| Green | `0xFF43A047` |
| Teal | `0xFF00897B` |
| Cyan | `0xFF00ACC1` |
| Blue | `0xFF1E88E5` |
| Indigo | `0xFF3949AB` |
| Purple | `0xFF8E24AA` |
| Pink | `0xFFD81B60` |
| Brown | `0xFF6D4C41` |
| Grey | `0xFF757575` |

Default color for new categories: cycles through the palette in order based on the current category count (`palette[categoryCount % palette.size]`). The first category gets Red, the second Orange, and so on — no two consecutive categories share a color unless the user has more than 12.

## Decisions & Alternatives

| Decision | Chosen | Alternatives Considered | Rationale |
|---|---|---|---|
| Dynamic color | Enabled by default on API 31+; brand-color fallback below | Disabled (as in GolfScore); dynamic only | Dynamic color feels native on modern Android; GolfScore disabled it but Trackr is a personal app where system color coherence matters more than brand consistency |
| Fallback palette generation | Material Theme Builder output (full tonal palette + contrast variants) | Hand-crafted colors; single seed at runtime | Theme Builder produces correct, accessible tonal relationships; same approach validated in GolfScore |
| Dark mode | System setting only (`isSystemInDarkTheme()`) | In-app toggle; always light | System setting respects user preference with zero UI needed; in-app toggle deferred until requested |
| Typography | M3 default | Custom Google Font; system font only | Default M3 is well-hinted and handles all scripts; custom font adds download complexity with minimal benefit at this stage |
| Shapes | M3 default | Custom radius overrides | No product reason to deviate; easier to change later if needed |
| Category color usage | Arbitrary ARGB as container; WCAG luminance for foreground | Derive tonal palette per category; use category color as accent only | Tonal palette generation per-category is expensive and inconsistent across dark/light; accent-only loses visual impact; container with luminance-computed foreground is simple and reliable |
| Foreground computation | WCAG relative luminance threshold | Fixed white foreground; Material `contentColorFor()` | `contentColorFor()` only works for theme colors; fixed white fails on light category colors; luminance is correct and standard |
| Preset palette size | 12 colors | 6 (too few); 24 (too many) | 12 covers the common tracking categories (food, mood, pain, sleep, exercise, etc.) without overwhelming the picker |
| Yellow → Amber | Amber `0xFFFFB300` | Yellow `0xFFFDD835` | Yellow has low edge contrast against light M3 surfaces; amber is visually distinct without needing a chip border |
| Default color assignment | Cycle through palette by category count | Fixed blue default; random | Cycling ensures visual variety automatically; fixed blue makes all uncustomized categories look identical; random is non-deterministic |

## Open Questions & Future Decisions

### Deferred

1. **In-app dark mode toggle** — system-only for now. Add if users request it.
2. **Custom font** — default M3 for now. Revisit if brand identity requires it.
3. **Additional preset colors** — palette can be extended without migration; it's a UI-only constant.
4. **Saturated colors in dark mode** — Red and Blue at full saturation may be visually heavy as containers on dark surfaces. Assess during UI implementation.
